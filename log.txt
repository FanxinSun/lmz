❯ what is motherboard GPU? Can it be used for state-of-art llm models?          

● What it is

  "Motherboard GPU" usually means one of three different things, and they're
  worth separating because only one of them is even a candidate:

  1. Chipset integrated graphics (the literal, historical meaning). Graphics
  built into the motherboard's northbridge — Intel GMA on G45, AMD 780G, NVIDIA
  nForce. These genuinely lived on the board. They died around 2010–2011 when
  Intel moved graphics onto the CPU die (Sandy Bridge) and AMD did the same with
  the Llano APUs.

  2. What people mean today: the iGPU on the CPU die. The HDMI/DisplayPort
  connectors on the I/O shield are just wires — the actual GPU is inside the
  CPU. That's why an Intel F-suffix chip or a non-G Ryzen gives you no picture
  from those ports at all. Intel UHD/Iris Xe/Arc, AMD Radeon 780M/890M, Apple's
  M-series GPU all fall here.

  3. Server board BMC video. An ASPEED AST2500/2600 soldered to the board,
  driving the IPMI/iDRAC remote console. Real motherboard GPU, ~16–64 MB, 2D
  framebuffer only. Zero compute. Not a candidate for anything.

  Can it run SOTA LLMs?

  Token generation is memory-bandwidth-bound, so the bus width decides almost
  everything:

  ┌─────────────────────────────────────────────────┬────────────────────┐
  │                     Memory                      │     Bandwidth      │
  ├─────────────────────────────────────────────────┼────────────────────┤
  │ DDR4-3200 dual channel                          │ ~51 GB/s           │
  ├─────────────────────────────────────────────────┼────────────────────┤
  │ DDR5-6000 dual channel                          │ ~96 GB/s           │
  ├─────────────────────────────────────────────────┼────────────────────┤
  │ Ryzen AI Max+ 395 (Strix Halo), 256-bit LPDDR5X │ ~256 GB/s          │
  ├─────────────────────────────────────────────────┼────────────────────┤
  │ Apple M4 Max / M3 Ultra                         │ ~546 / ~819 GB/s   │
  ├─────────────────────────────────────────────────┼────────────────────┤
  │ RTX 4090 / 5090                                 │ ~1008 / ~1792 GB/s │
  ├─────────────────────────────────────────────────┼────────────────────┤
  │ H100 SXM (HBM3)                                 │ ~3350 GB/s         │
  └─────────────────────────────────────────────────┴────────────────────┘

  Divide bandwidth by model size to get a ceiling. An 8B model at Q4 is ~4.7 GB,
  so a DDR5-6000 desktop tops out near 17 tok/s and realistically does 10–12. A
  70B dense at Q4 is ~40 GB → about 2 tok/s. Unusable.

  So, three tiers of answer:

  - Frontier closed models (Claude Opus, GPT-5-class, Gemini): no, and not on
    eight H100s either. The weights aren't public.
  - Frontier open-weight models: only on the wide-bus unified-memory class —
    Apple Silicon and Strix Halo — and mainly the MoE ones. A 120B MoE with ~5B
    active parameters only reads the active experts per token, so a 128 GB
    unified pool at 256 GB/s gets genuinely usable speeds. Dense 70B+ on a
    normal desktop iGPU does not work.
  - Small-to-mid open models (8B–14B, quantized): yes, fine, on any modern iGPU.
    That's a real, useful capability.

  Two practical gotchas worth knowing:

  On a normal desktop, the iGPU barely beats the CPU. They share the same DDR
  bus, so decode speed is roughly identical. The iGPU only wins on prompt
  processing (which is compute-bound) and power draw. Don't expect a speedup
  from switching backends.

  On your setup specifically — my notes say you have an x86 WSL2 box and an
  Apple Silicon Mac, so: WSL2 iGPU compute is rough. CUDA passthrough is solid,
  but Intel Level Zero and AMD ROCm through /dev/dxg are unreliable-to-absent.
  On that box, llama.cpp on CPU is the sane path. The Mac is the opposite story
  — Metal and MLX are the most mature integrated-GPU inference stack that
  exists, and its unified memory is the one "iGPU" that seriously competes.

  graphics the iGPU and CPU share one memory bus, so the honest comparison is

  is prefill, where 565 vs 48,300 GFLOP/s still isn't a fight, but on a 780M it

  The steps

  1. BIOS opens in EZ Mode. Press F7 for Advanced Mode (Enter if it asks to
     confirm).
  2. → to the Ai Tweaker tab.
  3. ↓ to Ai Overclock Tuner — it's the first item. Enter.
  4. Pick EXPO I. If your kit turns out to be XMP-only, the list will say
     D.O.C.P. or XMP I instead — either is fine, AM5 applies XMP profiles
     normally. Enter.
  5. If it then offers Profile 1 / Profile 2, take the DDR5-6000 one.
  6. ↓ to Memory Frequency and confirm it reads DDR5-6000MHz. Leave everything
     else on Auto — especially FCLK; AGESA will pick 2000 MHz for the 1:1 ratio
     you want.
  7. F10, then Enter to confirm.

  The next boot will scare you

  First boot after enabling EXPO runs full memory training: black screen for 30 
  seconds to ~2 minutes, fans spinning, no video, and the board may power-cycle
  itself once or twice on its own. The yellow DRAM Q-LED by the DIMM slots stays
  lit throughout. This is normal.

  Do not hit reset. Interrupting training is what produces the "EXPO bricked my
  board" stories. Only the first boot is slow; the trained values get cached.

  If it genuinely fails, the board auto-reverts after a few attempts and shows
  an overclock-failed prompt — press F1 to get back into BIOS and try EXPO II,
  or set 5600 manually. Worst case: PSU off, short the CLR_CMOS 2-pin header on
  the board for ~5 seconds.
